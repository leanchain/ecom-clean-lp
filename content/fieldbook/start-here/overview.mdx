The Commerce Fieldbook is an operator-focused knowledge system for the gaps between storefronts, catalogs, analytics, advertising platforms, search systems, and AI answer surfaces.

It starts with what a team can observe. SEO, GEO, AEO, CRO, accessibility, analytics, and reliability are useful disciplines, but they are filters—not the first question an operator usually asks.

## Choose the right starting point

Start with a **problem guide** when something looks wrong but the cause is not yet known. Problem guides separate symptoms, evidence, investigation moves, and premature conclusions.

Start with an **agent skill** when the problem is understood well enough to run a repeatable workflow. Skills state their required inputs, expected outputs, checks, and boundaries.

Start with a **playbook** when several people or systems need to coordinate an investigation and verification sequence.

Use **projects and references** to inspect the standards, official documentation, and open-source tools supporting the workflow.

<Callout type="evidence" title="Evidence rule">
A screenshot, API response, rendered page, catalog export, transaction record, or timestamped answer is evidence. A plausible explanation is still a hypothesis until it is tested.
</Callout>

## How pages are maintained

Every document has a review date and status. Stable means the workflow is suitable for routine use. Emerging means the underlying platform, protocol, or operating pattern is still changing. Experimental material must not be treated as a standard or a guaranteed outcome.

## Recommended reading order

1. Read the evidence model.
2. Learn how to use agent skills safely.
3. Open the problem closest to what your team observes.
4. Follow its related skill or playbook.
5. Confirm external requirements against the linked primary source.
