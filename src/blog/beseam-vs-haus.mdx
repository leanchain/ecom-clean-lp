## TL;DR

Haus is positioned around **incrementality experiments** (plus causal MMM and calibrated reporting).

Beseam is positioned around **operational safety for Shopify changes**: no experiment required—if KPIs dip after a deploy, Beseam ties it to the change diff and guides the fastest safe rollback.

## What Haus claims (from the research you shared)

- Incrementality experiments as the core product.
- Geo tests / fixed geo tests / time tests for measuring impact.
- Enterprise + experts/PhDs guided model.

## The gap: change incidents happen even when nobody is “testing”

Agencies routinely ship:

- theme updates
- schema and FAQ changes
- promo eligibility edits
- app embeds / pixels / checkout customizations

Those changes can cause regressions, even if marketing measurement is perfect.

That’s why Beseam’s loop is different:

1) capture the change  
2) detect the anomaly  
3) attribute to the diff  
4) run a rollback/remediation runbook  
5) verify recovery
