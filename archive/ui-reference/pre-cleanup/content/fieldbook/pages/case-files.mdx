A case file records what happened, what changed, and how the result was checked. It is useful only when the source material can be shared safely and the account does not pretend to know more than the investigation proved.

## Required sections

- Initial signal
- Affected product, page, event, or journey
- Evidence collected
- Explanations considered
- Change made
- Retest method
- Result
- Open questions

## Publication rules

Remove customer, employee, transaction, and commercially sensitive data unless publication has been approved. Estimates must remain labeled as estimates. A technical fix should not be presented as a revenue win without a suitable measurement design.

<Callout type="evidence" title="No invented case studies">
Until a real case can be verified and published, the Fieldbook will provide methods and templates rather than fictional success stories.
</Callout>

## Submit a case

Use the contribution page. Include dates, source material, the exact change, and the retest that followed it.
